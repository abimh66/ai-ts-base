# 0002 — The frontend is a router-only SPA: loaders own data fetching, no SSR framework

The frontend is a **router-only TanStack Router SPA** (Vite), not a TanStack Start app. Route `loader`s own a route's primary data: the loader calls `context.queryClient.ensureQueryData(...)` and the component reads `useSuspenseQuery` off the **same** `queryOptions`, so `data` is never `undefined` and pages have no `isLoading` branch. TanStack Query still owns the cache, and the router provides `defaultPendingComponent` / `defaultErrorComponent` / `defaultNotFoundComponent` with route-local overrides. Query defaults live in `lib/query.ts` (30s stale, one retry, none on 4xx, none for mutations).

**Why not TanStack Start.** The conventions above are a **Router** feature, not a Start one — they run unchanged on the current Vite SPA once `queryClient` is in router context. Start's value is SSR/streaming and `createServerFn`, and this app needs neither: the backend is the separate Hono server (`apps/api`) and the deploy is static with data fetched in the browser — which is exactly what the SPA already does. Migrating would be pure churn (swap the router plugin, delete `index.html`, restructure `__root.tsx`) for no capability gained. Start stays a deferred option, revisited only when a concrete SSR/server-function need appears.

**Consequences.** No `ssr: false`, no per-route SSR toggles, no server entry — there is no Start server at runtime. Anything that polls stays a plain `useQuery` with `refetchInterval` and inline states, because a loader resolves once and would block navigation on a query that refetches every 1.5s. The `note` detail page is the worked example: it is loader-backed, but switches on `refetchInterval` while a note is `Enriching`. `router.invalidate()` is reserved for the error-retry path, never for refreshing data after a mutation — mutations `invalidateQueries` the affected keys instead.

**Naming follows from this.** A feature exposes two reads of the same data: `useX` (non-suspending `useQuery`) for chrome that renders outside a loader — the sidebar — and `useXSuspense` for route components, which the loader has already primed. Using the suspending form in the shell would block the whole app on data the shell does not need.
